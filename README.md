## 环境说明

本机没有全局 npm，工具链已内置在 `wuguan/.toolchain/node/`（Node v22.13.0 官方发行版，含 npm 10）。

```bash
# 安装依赖（首次）
npm.cmd install

# 启动开发服务器（默认 http://localhost:5173）
npm.cmd run dev

# 构建产物
npm.cmd run build

# 预览构建产物
npm.cmd run preview
```

> `npm.cmd` 是项目根下的包装脚本：它会先 `cd` 到项目目录再调用 `wuguan\.toolchain\node\npm.cmd`（系统没有全局 npm，工具链已内置）。

## 与需求文档的对照

- 技能 id 与 §3 一一对应（foraging / fishing / hunting / excavation / farming / cooking / baking / preserving / brewing / spiceMixing / craftsmithing / knife / heatControl / flavorArtistry / plating / tasteAcumen / spiritSummoning / gastronomy / preservation / exploration）
- 背包/仓库使用 `{ itemId: quantity }` 对象形式（文档示例为数组 `[{id, quantity}]`），便于 Vue 响应式与查找，结构语义一致
- 存档当前存于 LocalStorage，`SaveManager` 接口预留 IndexedDB 切换点（§10.1 主存储为 IndexedDB，后续迭代）

### 风味搭配册：21 条永远点不亮的组合已重写

做「在哪做」反查时发现：**28 条搭配里只有 7 条能在现有配方中找到同时含全部食材的做法**，另外 21 条（含页面举例的「番茄与罗勒」——罗勒只出现在 2 条配方里且都不含番茄）永远无法点亮，约锁住 28,700 金币奖励。

### 能量饼干：溢出后新增两个出口（2026-09-10）

用户反馈：能量饼干只能加离线时长，而离线上限封顶 12h，**多的饼干就没用了**。

核实后的数字比预想更严重：饼干的效果是「离线上限 +4h」（**物品效果属固定数据，不可改**），而封顶 +12h → **一生只用得上 3 块**；可它按消耗品在发放——**30 项成就就发 38 块**（12.7 倍超额），外加烘焙 Lv20 配方可无限制作、以及探索/竞技场/挑战塔/卡牌/吉祥物/名厨/节庆 7 处可重复产出。原有兜底等于没有：半价卖 60 金币、或炼金换成等值的草莓蛋糕。对比**神秘调料**——同样珍贵，但战斗内可无限使用，所以从不出问题。

| 出口 | 位置 | 规则 |
| --- | --- | --- |
| 🍪 **能量补给** | 对决 / 试炼 / 名厨 / 竞技场 / 挑战塔的战斗面板 | 消耗 1 块 → 立刻回 **25%** 品鉴值 + **5 回合**「精力充沛」（命中 +8、攻速 +10%），自身冷却 4 回合（与料理同规格） |

## 发布（GitHub Releases）

- **自动发布**：推送 `v*` 标签即触发 `.github/workflows/release.yml`（GitHub Actions）：安装依赖 → `vite build` → Electron 桌面打包 → 创建 Release 并上传 Windows 可执行 zip。
  ```bash
  git tag v1.0.0 && git push origin v1.0.0
  ```
  > 附件命名：**文件名用 ASCII**（`culinary-idle-<tag>-win32-x64.zip`），中文名放在 release 资产的 **display label**（「美食放置：食之契约 vX.Y.Z 桌面版」）。原因：GitHub 会剥掉附件名里的非 ASCII 字符（早期版本附件名因此变成 `-win32-x64.zip`）。
- **手动打包**（本机）：`npm.cmd run build` → 复制 `dist/` 到 `lmewexe/dist/` → `python lmewexe/fix_paths.py` → `cd lmewexe && npm run pack`（产物在 `lmewexe/release/`）。
